# 🎉 송년회 랜덤 미니게임 배틀

QR코드 하나로 수십 명이 스마트폰 브라우저로 접속해 미니게임을 동시에 하고, 매 라운드 순위가 실시간으로 발표되는 웹앱입니다.

- **참가자** `/join/{코드}`: 모바일 화면. 회원가입이나 앱 설치 없이 닉네임만 입력하면 됩니다.
- **사회자** `/host`: 노트북용 관리 화면. 비밀번호로 보호됩니다.
- **대형 스크린** `/screen/{코드}`: 빔프로젝터·TV 송출용 16:9 화면(1920×1080 기준, 창 크기에 맞춰 자동으로 확대·축소).

---

## 1. 아키텍처

```
 [참가자 폰 ×100] ─┐                         ┌─ RoomManager (상태 머신·채점·순위)
 [사회자 노트북]  ─┼─ WebSocket(Socket.IO) ─┤   ├─ games/* (게임별 서버 판정 모듈)
 [대형 스크린]    ─┘     + Next.js 화면      │   └─ data/rooms/{CODE}.json (원자적 저장)
                         (단일 Node 프로세스: server.ts)
```

**Supabase 대신 단일 Node 서버(Next.js + Socket.IO)를 고른 이유**
- 모든 판정(정답, 반응속도, 연타 상한, 마감 시각)을 서버 한 곳에서 하기 때문에 조작할 수 없고, 타이밍 기준도 하나뿐입니다.
- 외부 DB나 계정 없이 `npm start` 한 번으로 실행됩니다. 하루짜리 행사 규모(100명 이하)에서는 단일 인스턴스로 충분합니다.
- 상태는 메모리에 두고, 변경될 때마다 JSON 파일로 원자적으로 저장합니다. 서버가 재시작되면 저장된 진행 상태·점수·타이머를 그대로 복구합니다.
- 단점: 인스턴스를 1개로만 운영해야 합니다(수평 확장 불가). 행사 용도라면 문제가 없습니다.

### 폴더 구조
```
server.ts                     커스텀 서버 (Next + Socket.IO)
src/server/room.ts            상태 머신, 점수 계산, 순위, 영속화, 브로드캐스트
src/server/socket.ts          이벤트 라우팅, 관리자 인증, 레이트리밋
src/server/games/*.ts         게임별 서버 로직 (공통 GameModule 인터페이스)
src/server/questionBank.ts    내장 문제 + 사용자 추가 문제(JSON)
src/data/*.ts                 넌센스 36 / 초성 38 / OX 34 문제 (정답·해설·난이도·카테고리) + 타자 문장 30개
src/components/games/*.tsx    게임별 참가자 화면
src/app/{join,host,screen}    참가자 / 사회자 / 대형 스크린 페이지
scripts/sim.ts                봇 30명으로 전 게임을 돌리는 통합 테스트
scripts/verify-data.ts        문제 데이터 검증 (중복, 초성 모호성, 정수 나눗셈)
```

### 게임 상태 (서버만 바꿀 수 있음)
`LOBBY → GAME_INTRO → COUNTDOWN(3초) → PLAYING → CALCULATING → ROUND_RESULT → TOTAL_RANKING → (다음 게임 …) → FINISHED`

- 단계는 사회자 버튼 또는 서버 타이머로만 넘어갑니다. 클라이언트는 "요청"만 보낼 수 있습니다.
- `PLAYING`은 게임마다 여러 step으로 나뉩니다. 퀴즈는 문제와 정답 공개가 번갈아 나오고, 나머지 게임은 단일 step입니다.
- `CALCULATING`에서 서버가 점수를 확정합니다. 사회자가 "결과 공개"를 누르면 그때 누적 점수에 반영합니다. 라운드당 1회만 반영되며, 같은 결과를 두 번 반영하려 해도 차단됩니다.

### 데이터 모델 (`data/rooms/{CODE}.json`)
| 필드 | 설명 |
|---|---|
| `code`, `hostToken` | 방 코드, 사회자 인증 토큰 |
| `settings` | 타이틀, 라운드 수, 활성 게임, 사칙연산 난이도, 중간 참가 허용 |
| `phase`, `phaseStartedAt/EndsAt`, `paused`, `timerAt` | 현재 단계와 서버 기준 시각 (재시작 후 복구용) |
| `players{id → {token, nickname, total, wins, lastScore}}` | 참가자 (token으로 재접속을 인증) |
| `round{gameId, data, players, participants, steps, stepIndex}` | 진행 중인 라운드 (정답 데이터는 서버에만 존재) |
| `history[]` | 라운드별 결과 (순위, 점수, 기록, 누적, 순위 변화) |
| `ranking[]`, `bag[]`, `playedGames[]`, `usedQuestions{}` | 누적 순위, 랜덤 가방, 진행 기록, 사용한 문제 |

### 실시간 동기화 · 공정성
- **시계 보정**: 클라이언트가 접속할 때와 30초마다 `time:ping`을 6번 보내고, 왕복 시간(RTT)이 가장 짧은 표본으로 서버와의 시차를 계산합니다(NTP 방식). 카운트다운과 타이머는 모두 이 서버 시각을 기준으로 표시됩니다.
- **카운트다운 동시 시작**: 서버가 시작 시각을 "지금 + 0.4초"로 정해 내려보내므로, 모든 기기가 같은 순간에 3-2-1을 시작합니다.
- **마감**: 서버는 마감 시각 + 0.6초(네트워크 지연 보정)까지만 제출을 받습니다. 그 이후 제출은 거부합니다.
- **정답 비공개**: 문제 단계의 공개 상태에는 보기만 들어 있고, 정답·분포는 공개 단계에서만 내려갑니다. 시뮬레이션에서 자동으로 검사합니다.
- **조작 방지**: 연타는 초당 20회를 넘으면 잘라냅니다. 반응속도는 GO 신호를 서버가 참가자별 무작위 시점에 보내며, 클라이언트가 보고한 ms가 서버에서 잰 경과 시간보다 짧을 수 없고 100ms 미만이면 반칙입니다. 문제를 중복 제출하거나 이미 지난 문제에 답하면 거부합니다. 소켓당 초당 40개로 이벤트를 제한하고, 관리자 비밀번호는 5회 틀리면 60초간 잠깁니다.
- **연결 끊김 자동 퇴장**: 참가자 연결이 끊긴 상태(빨간불)가 10초 동안 계속되면 자동으로 퇴장시킵니다. 사회자 화면의 대회 설정에서 사용 안 함 / 10·30·60초로 바꿀 수 있습니다. 퇴장되면 점수도 사라지고, 새 닉네임으로 다시 입장해야 합니다.
- **재접속**: 참가 정보 `{playerId, token}`을 localStorage에 저장해 두고, 소켓이 다시 연결될 때마다 자동으로 `player:resume`을 보냅니다. 점수는 서버에 있으므로 새로고침해도 유지됩니다.

### 점수 (라운드당 0~1000점, 서버 계산)
| 게임 | 방식 |
|---|---|
| 👆 연타왕 (10초) | 터치 수 ÷ 1등 터치 수 × 1000 |
| 🧮 사칙연산 (30초) | 정답 100 + 속도 보너스(최대 50) − 오답 30 → 1등 대비 환산 |
| 🎨 색깔 함정 / ⚖️ 숫자 비교 / 🎯 숫자 감각 (20초) | 사칙연산과 같음 |
| 🔢 순서 맞추기 (25초) | 4개를 작은 순서대로 모두 맞히면 정답, 점수 방식은 사칙연산과 같음 (보너스 기준 8초) |
| 🎯 움직이는 과녁 (15초) | 명중 100 + 속도 보너스(최대 50) − 빗나감 10 → 1등 대비 환산. 맞힐수록 과녁이 작고 빨라짐 |
| 🥤 컵 속 공 찾기 (2문제, 컵 3개→5개) | 문제당 500 × (정답 60% + 남은 시간 40%). 섞는 순서를 서버가 정해 모든 화면에서 동시에 재생 |
| ⏱️ 10초를 잡아라 (1회) | 오차가 작을수록 높은 점수(3초 이상 차이는 0점) → 1등 대비 환산. 대형 화면 타이머도 숨김 |
| 🧩 도형 퍼즐 (25초) | 조각을 90°씩 돌려 빈칸과 같으면 정답. 점수 방식은 사칙연산과 같음 |
| 🥁 리듬 마스터 (약 12초) | PERFECT 100 · GREAT 70 · GOOD 40, 헛터치 −20 → 만점 대비 × 1000. PC는 스페이스바 |
| ⌨️ 빠른 타자 (30초) | 문장 일치(띄어쓰기 무관, 붙여넣기 차단), 점수 방식은 사칙연산과 같음 (보너스 기준 12초) |
| 🤣 넌센스 (3문제×10초) / 🔤 초성 (3문제×15초, 주관식) / 🙆 OX (5문제×6초) | 문제당 (1000/문제수) × (정답 60% + 남은 시간 비율 40%). 접속 중인 참가자가 모두 답하면 남은 시간을 기다리지 않고 바로 정답을 공개합니다 |
| ⚡ 반응속도 (3회) | 평균 ms (반칙·미응답은 1000ms) → 1등 평균 ÷ 내 평균 × 1000 |
| 🧠 숫자 기억 (60초) | 최대 자릿수 + 평균 입력 속도 가산(1자리 미만) → 1등 대비 환산 |

- 무응답이나 시간 초과는 0점입니다.
- 동점이면 공동 순위입니다(1, 1, 3 방식).
- 누적 순위는 총점 기준입니다. 총점이 같으면 공동 순위이고, 표시 순서만 라운드 1위 횟수 → 최근 라운드 점수 → 닉네임 순으로 정합니다.

### 랜덤 게임 선택
활성화된 게임으로 "가방"을 만들어 섞은 뒤 하나씩 꺼냅니다. 그래서 모든 게임을 한 번씩 한 다음에 반복되고, 같은 게임이 연속으로 나오지 않습니다. 사회자는 특정 게임을 직접 고르거나, 소개 단계에서 "다른 게임으로 바꾸기"를 누를 수 있습니다.

### 게임 추가하기
1. `src/server/games/myGame.ts`에 `GameModule`을 구현합니다(`create / initPlayer / onAction / playerView / publicPayload / finalize`).
2. `src/server/games/registry.ts`에 등록하고, `src/shared/gameMeta.ts`에 이름·색상·설명을 추가합니다.
3. `src/components/games/index.tsx`에 참가자 화면 컴포넌트를 연결합니다.

"개인별 연속 문제" 형식은 `makeStreamGame({gen, check})`, "동시 퀴즈" 형식은 `makeQuizGame({build})`로 몇십 줄이면 만들 수 있습니다. 숫자 크기 비교, 순서 맞추기, 빠른 타자, 숫자 감각이 이 방식으로 추가한 확장 게임입니다(`src/server/games/streamGames.ts`).

## 2. 로컬 실행

Node.js 20 이상이 필요합니다.

```bash
npm install
cp .env.example .env        # ADMIN_PASSWORD 변경
npm run build
ADMIN_PASSWORD=비밀번호 npm start      # http://localhost:3000
# 개발 모드: ADMIN_PASSWORD=비밀번호 npm run dev
```

서버를 시작하면 콘솔에 `같은 Wi-Fi: http://192.168.x.x:3000` 주소가 출력됩니다. 휴대폰은 이 주소로 접속해야 합니다(localhost는 휴대폰에서 열리지 않습니다). 사회자 화면에서 이 주소를 누르면 QR코드가 그 주소로 바뀝니다.

### 환경변수
| 이름 | 설명 |
|---|---|
| `ADMIN_PASSWORD` | 사회자 비밀번호 (**필수로 변경**, 기본값 `party2026`) |
| `PORT` | 포트 (기본 3000) |
| `DATA_DIR` | 상태 저장 폴더 (기본 `./data`) |
| `NEXT_PUBLIC_BASE_URL` | QR에 넣을 공개 주소 (빌드할 때 반영됨, 선택) |

데이터베이스 SQL은 필요 없습니다. 상태는 `DATA_DIR/rooms/*.json`에, 사용자가 추가한 문제는 `DATA_DIR/custom-questions.json`에 저장됩니다.

## 3. 테스트
```bash
npm run verify:data   # 문제 데이터 검증
npm run sim           # 봇 30명 × 17개 게임 통합 시뮬레이션 (SIM_GAMES=cups,rhythm 처럼 일부만 가능) (약 5분, BOTS=100 으로 부하 테스트)
npm run typecheck
```
시뮬레이션이 검증하는 항목: 비밀번호·토큰 위조 거부, 닉네임 중복, 재접속, 참가자의 관리자 명령 거부, 정답 정보 비노출, 중복 제출과 마감 후 제출 차단, 반응속도 조작 차단, 점수 범위와 정렬, 결과 중복 반영 차단, 라운드 수 제한, 디스크 저장과의 일치.

### 여러 휴대폰으로 테스트하기
1. 노트북과 휴대폰을 같은 Wi-Fi에 연결하고 `npm start`를 실행합니다.
2. `/host`에 로그인해 방을 만들고, 사회자 화면에서 LAN 주소를 선택합니다.
3. "대형 스크린 열기"를 누르고 휴대폰 3~4대로 QR을 스캔합니다.
4. 게임 하나를 직접 선택해 진행한 뒤, 한 휴대폰을 새로고침하거나 비행기 모드를 잠깐 켰다 꺼서 점수가 유지되는지 확인합니다.

## 4. 배포 (WebSocket을 상시 유지하는 서버 필요)
Vercel 서버리스는 WebSocket 서버를 계속 띄워 둘 수 없어 **적합하지 않습니다**. 다음 중 하나를 쓰세요.
- **Render / Railway / Fly.io**: Dockerfile 또는 `npm install && npm run build` → `npm start`로 배포합니다. 인스턴스는 **1개**로 두고, `/data` 영구 볼륨을 붙이고, `ADMIN_PASSWORD`를 설정합니다.
- **Docker**: `docker build -t party . && docker run -p 3000:3000 -e ADMIN_PASSWORD=... -v party-data:/data party`
- **행사장 노트북 + 터널**: `npm start` 후 `cloudflared tunnel --url http://localhost:3000`으로 HTTPS 주소를 받아 QR 주소로 지정합니다.

## 5. 행사 당일 체크리스트
- [ ] `ADMIN_PASSWORD`를 변경했는지, 배포 주소가 HTTPS로 접속되는지 확인
- [ ] 리허설: 휴대폰 3대 이상으로 게임 2~3개, 새로고침 후 복귀 확인
- [ ] 행사장 Wi-Fi 또는 LTE에서 QR 접속 확인 (사내 Wi-Fi의 기기 간 통신 차단 여부)
- [ ] 노트북 전원 연결, 절전·화면 꺼짐 해제, 대형 스크린 창은 F11 전체 화면
- [ ] 대형 스크린에서 🔇를 클릭해 효과음 켜기 (브라우저 정책상 클릭이 필요함)
- [ ] 라운드 수와 사용할 게임 설정, 중간 참가 허용 여부
- [ ] 참가자 안내: "화면을 켜 두세요, 무음 모드를 해제하면 효과음이 나와요"
- [ ] 문제가 생기면: 라운드 취소(점수 미반영), 강제 종료(지금까지의 기록으로 집계), 서버 재시작(진행 상태 자동 복구)
- [ ] 끝나면 CSV와 순위 이미지 다운로드

## 6. 알려진 제약
- iOS Safari는 진동(Vibration API)을 지원하지 않습니다. 진동 대신 시각 효과와 효과음으로 피드백합니다.
- 일시정지는 카운트다운과 퀴즈형 게임(넌센스·초성·OX)에서만 됩니다. 개인별로 진행되는 게임은 공정성 때문에 일시정지 대신 강제 종료나 라운드 취소를 쓰세요.
- 폰트(Pretendard, Black Han Sans)는 CDN에서 불러옵니다. 오프라인이면 시스템 한글 폰트로 표시됩니다.
